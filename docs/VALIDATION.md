# AskMarker 0.8.0: 여러 AI 입력창·기본값

2026-10-17. 설치 ZIP의 실행 파일을 격리 Chromium에 로드하고 **19개 검증 모음 모두 통과**했습니다. 배포 시 실행 파일 해시를 검증한 설치본과 다시 대조합니다.

- 기존 입력·안내 코드는 ChatGPT 주소에서만 허용됐습니다. 제한을 제거하고 `composer-sites.js`에서 서비스별 편집기 인식을 분리했습니다. Gemini·Grok과 일반 textarea/ProseMirror 입력창에서 안내, 기존 내용 뒤에 추가, 확인된 입력 뒤 체크 해제, 중복 방지를 검사했습니다. 전송은 수행하지 않습니다.
- 입력창 위에 350ms 머무르거나 클릭하면 안내가 뜹니다. 단순 통과·입력 중·한글 조합 중에는 hover 안내를 취소합니다. 안내 ON/OFF와 수동 추가는 독립적으로 동작합니다.
- 여러 입력창이 있으면 사용자가 가리킨 입력창을 사용합니다. 지정되지 않은 여러 후보 중 하나를 임의로 고르지 않습니다. 입력창 교체 시 같은 ID·태그·라벨을 확인하거나 유일한 입력창을 다시 찾습니다.
- 기본 글씨 크기는 시스템·브라우저 기본이며 직접 입력은 80–160%, 숫자 입력과 슬라이더를 지원합니다. 이전 Current 설정은 System으로 읽고 기존 Custom 값은 보존합니다.
- 새 질문 기본색은 아이콘의 `#6554e8`입니다. 기존 보라 팔레트 항목을 교체했으며 8색을 유지합니다. 이전 질문의 색 키와 기록은 수정하지 않습니다. 색이 없던 구버전 기록의 노랑 복원은 유지합니다.

## v0.6.1 드래그 후 질문 추가

드래그는 읽기 동작으로 취급합니다. 선택 영역 옆의 작은 **질문 추가** 버튼만 표시하며, 누르기 전에는 포커스·입력 세션·임시 형광펜·저장 기록을 만들지 않습니다. 버튼을 눌렀을 때 원문을 정확히 다시 확인하고 글 아래에서 질문을 작성합니다.

`selection-action-test.cjs`는 실제 MV3 확장에서 다음을 통과했습니다.

- 버튼을 누르지 않는 실제 마우스 드래그 10회: 기본 선택 표시와 본문 위치 유지, 입력창·초안·저장 기록 없음.
- 질문 추가 → 빈 입력창 취소 → 같은/다른 원문 재선택 10회.
- Esc·다른 곳 클릭·선택 해제 시 버튼만 닫힘.
- 기존에 입력 중인 질문은 새 드래그로 바뀌거나 삭제되지 않음. 새 버튼을 눌러야 별도 원문에 대한 작성이 시작됨.
- 저장된 표시 보존, 패널을 접은 상태에서도 추가, 읽기 모드 OFF/ON에서 기록 보존.
- 버튼이 선택한 원문을 따라 스크롤·크기 변경에 대응. 내부 스크롤에 가려지거나 변경된 원문에는 남아 있지 않음.
- 키보드 Enter로 버튼 실행, 대화 이동 시 임시 선택만 정리, 런타임 오류 없음.

`selection-button.png`와 `after-question-add.png`는 이 흐름을 실제 확장으로 촬영한 검증용 HTML 화면입니다.

## 유지된 수정

1. 연결된 실제 ChatGPT에서 현재 입력창은 ID 없는 `[data-composer-markdown][contenteditable="true"]`였습니다. 이전 코드는 `#prompt-textarea`만 찾았습니다. 새 속성을 추가하고 이전 구조도 유지합니다. 이 구조는 앞선 v0.6.0 작업에서 읽기 전용으로 관찰한 내용입니다. v0.6.1을 실제 계정에 설치해 조작한 것은 아닙니다.
2. 이전 v0.5.2에서 말풍선 호스트를 문단 다음 형제로 넣으면 가로 flex·grid·contents 레이아웃의 옆 칸으로 배치됐습니다. 동일 HTML과 실제 마우스 드래그로 재현했습니다. 수정본은 이런 경우 원문 블록 안에서 아래로 이어지게 하고, 말풍선 자체에 폭과 흐름을 지정합니다. 사이트의 기존 본문 노드는 옮기지 않습니다.
3. 입력창 클릭은 즉시 입력 대신 포인터 옆 확인창을 엽니다. **모아서 입력**에서 다시 대화·대상 입력창·미저장 작성 상태를 확인하고 추가합니다. 포커스 이동 때문에 뒤늦게 발생한 스크롤 이벤트가 확인창을 즉시 닫지 않도록 처리했습니다. 휠·외부 클릭·Esc·크기 변경·대화 이동으로 닫힙니다.
4. 입력창에 현재 들어 있는 원문/질문 쌍으로 중복을 판별합니다. 예전 자동 추가 이력이 새 확인창을 막지 않으며, 입력창을 비우면 다시 확인해 넣을 수 있습니다. 기존 로컬 기록은 삭제하지 않습니다.
5. 생성 프롬프트에서 인용문 안의 지시문을 실행하지 말라는 안내 문장을 제거했습니다. 인용 원문과 질문은 그대로 유지합니다.

### 입력 확인창

- 현재 ID 없는 입력창과 예전 textarea/ID 입력창 지원.
- 실제 마우스 클릭 위치 옆에 표시. 클릭만으로는 입력되지 않음.
- 확인 버튼, 나중에, Esc, ON/OFF 저장, 패널 수동 추가·복사·미리보기.
- 기존 입력 보존, 정확한 인용/질문 쌍, 이미 있는 쌍의 중복 방지.
- 미저장 초안/수정이 있으면 확인 버튼 비활성화. 취소한 질문 제외.
- 입력창을 지운 경우 재확인 가능. 새 탭에도 자동 입력 없이 확인창만 제공.
- 같은 대화에서 입력창 DOM이 교체되면 현재 보이는 유일한 입력창을 다시 확인.
- 대화 이동 시 확인창 종료, 자동 전송 없음, 페이지/확장 실행 오류 없음.

### 원문 아래 말풍선과 기존 회귀

- 6개 배치: 일반 block, flex column, flex row, grid, contents, inline/flex.
- 앞선 v0.6.0 작업의 row/grid/contents 비교 결과는 `bubble-flow-comparison.json`에 보관. v0.6.1의 현재 결과는 `bubble-flow-results.json`에서 별도 확인.
- 글 영역과 말풍선 좌표를 측정하여 수직 위치와 가로 영역 겹침을 확인.
- 여러 문단 선택 뒤 마지막 문단 아래 표시, 내부 스크롤·크기 변경·새로고침 복원.
- 여러 본문 구조에서 빈 말풍선 취소·재선택 10회 반복. 기본/현대 본문, 정/역방향 선택.
- 8색, 포커스 후 형광펜 유지, 말풍선/목록 편집·삭제 동기화, 같은 원문의 다른 질문 유지.
- 읽기 모드 OFF/ON 및 초안 보존, 패널 접기, 재렌더링, 대화별 격리, 원문이 바뀌면 잘못 붙이지 않고 목록에 유지.
- 백업/가져오기, 저장 실패·지연, 이전 기록, `Document.host` 이름 충돌 회귀.

화면 이미지는 모두 합성 예시 문장을 쓰는 검증용 HTML에 실제 확장을 로드해 캡처했습니다. 회사 자료나 실제 ChatGPT 대화 내용은 포함하지 않습니다.
