# 0.11.0 테마 모듈

`domain/theme.js`는 팔레트 색상으로 배경·버튼·hover·포커스·대비 글자 토큰을 만드는 순수 함수입니다. `ui/theme.js`는 이름이 지정된 AskMarker CSS 변수만 적용하며 기록을 읽거나 쓰지 않습니다. 본문 작성 카드마다 기존 저장 색상을 유지하면서 `applyCommentColor`로 밝은/어두운 화면별로 톤을 낮춘 배경과 테두리/글자색을 적용합니다. 작성 표면과 입력란·설명·꼬리는 개별 Q 색상을 따르며 전역 테마와 독립적입니다. (0.11.1에서 원색 90% 채우기를 대체)

전체 테마는 기존 마지막 선택 색상 설정을 사용합니다. 다른 Q를 클릭해도 전역 테마는 유지하고 원문·포인터의 해당 항목 색만 따라갑니다. 내보내기 페이지도 같은 공용 토큰을 읽으며 기존 인증/저장 흐름은 독립적입니다. 표시 명칭만 Q로 바꾸고 기존 question/markIds/백업 키는 바꾸지 않습니다.

# AskMarker 모듈 구조

## 검토 결과와 적용 원칙

0.6.4는 CSS, 화면 생성, 선택 인식, 원문 위치 복원, 작성 상태, 저장, 프롬프트 입력이 하나의 즉시 실행 함수에 들어 있었습니다. 글꼴처럼 표시만 바꾸는 기능도 같은 파일을 수정해야 했고, 일반 입력창 제외 규칙이 ChatGPT의 메일 작성 박스까지 막았습니다.

0.7.0은 **변경 이유가 같은 코드를 한 모듈에 모으는 단일 책임 원칙**, **모듈 내부 상태 은닉**, **콜백을 통한 의존성 주입**, **순수 데이터 처리와 DOM·저장소 부작용의 분리**를 적용합니다. 파일을 나눠 같은 전역 변수를 공유하는 방식은 사용하지 않습니다. 각 파일은 CommonJS 모듈 스코프를 가지며, 명시적으로 가져온 API만 사용합니다.

모듈화가 모든 영향 가능성을 없애지는 않습니다. 예를 들어 글꼴을 바꾸면 줄바꿈과 원문의 화면 좌표는 달라집니다. 따라서 좌표를 원문의 식별자로 저장하지 않고 정확한 메시지 ID·텍스트·오프셋으로 연결하며, 말풍선은 문서 흐름 안에 둡니다. 변경 범위를 구조적으로 줄이고 경계 검증으로 남은 영향을 확인합니다.

## 반드시 유지할 계약

- 표시 설정은 `qb:appearance:*`에만 저장합니다. `qb:note:`와 `qb:prompt-choice:`를 수정하지 않습니다.
- 글꼴·포인터 설정은 전체 질문 화면 재생성을 호출하지 않습니다. CSS만 바꾸므로 작성 내용·포커스·원문 연결을 재설정하지 않습니다.
- 글꼴은 외부 다운로드 없이 로컬/시스템 글꼴을 사용합니다. AskMarker UI와 읽기 모드의 답변 문단에 적용하고 코드 글꼴은 유지합니다. 없는 글꼴은 지정된 기본 계열로 대체됩니다.
- 원문 저장은 화면 좌표가 아닌 원문 식별 정보에 의존합니다. 기존 `include-buttons`/이전 인덱스 규칙은 그대로 유지하고, 새 기록만 `answer-content` 인덱스를 사용합니다.
- ChatGPT 작성 박스는 확인된 답변 안에서만 허용합니다. 실제 입력창·사용자 메시지·관련 없는 편집기까지 허용하지 않습니다.
- 말풍선을 ProseMirror/코드 스크롤 영역 안에 삽입하지 않습니다. 박스가 끝난 아래에 둬 편집기 문서를 오염시키거나 잘리지 않게 합니다.
- 입력 어댑터가 실제 추가 결과를 확인한 뒤 컨트롤러가 전달한 묶음의 체크를 해제합니다. 추가 도중 저장한 새 질문은 해제하지 않습니다. 실패·취소·단순 복사는 해제하지 않습니다.
- 질문 내용, 활성 색상 대상, 프롬프트 포함 여부, 읽기 모드, 패널 표시 상태는 서로 다른 상태입니다.

## 0.7.6: 글씨 크기와 메뉴 위치

- `domain/appearance.js`의 `sizeOf`가 현재 크기·시스템·직접 조절 모드와 80–160% 범위를 검증합니다. 기본은 현재 크기입니다. `qb:appearance:text-size:v1`만 사용합니다.
- `ui/appearance.js`가 `--askmark-ui-scale`을 설정합니다. `base.css`·`panel.css`의 글씨 크기가 이 값을 따르며 본문 아래 질문 말풍선에도 상속됩니다. 사이트 원문 크기는 변경하지 않습니다.
- 시스템 크기는 확장 Shadow DOM 안의 CSS `medium` 측정값을 기준으로 합니다. 브라우저 기본 크기가 바뀌면 `ResizeObserver`로 갱신합니다. OS 텍스트 배율을 직접 읽는 기능이 아니며 브라우저 확대/축소는 별도로 정상 적용됩니다.
- `ui/dock.js`는 손잡이에서만 포인터를 캡처합니다. 드래그 중단 시 위치를 복구하며 읽기 모드·펼침 버튼의 클릭을 가로채지 않습니다. 키보드 방향키·Home/End도 지원합니다.
- 메뉴 위치는 화면에서 이동 가능한 세로 구간의 비율로 `qb:appearance:dock-position:v1`에 저장합니다. 창 크기·글씨 크기 변경 및 펼침/접힘 후에도 화면 안으로 배치합니다.
- 두 모듈은 지연된 초기 읽기와 사용자 조작의 순서를 구분하고 설정만 저장합니다. 앱은 hydrate/change 연결만 담당합니다. 모듈 계약 검사에 `ui/dock.js`를 포함합니다.
- `dock-text-size-test.cjs`는 실제 마우스 이동, 위치 복원, 드래그 중단, 키보드, 브라우저 기본 크기 변경, 여러 탭 동기화와 크기 변경 중 초안·질문·체크·형광펜 보존을 검사합니다.

## 0.8.0: 여러 AI 입력창과 기본값

- `composer-sites.js`가 ChatGPT, 관찰한 Gemini/Grok 입력창, 일반 textarea/편집기 선택자를 구분합니다. 새 서비스의 DOM 규칙은 여기서 추가하며 원문 저장·복원과 분리합니다.

- 앱은 350ms hover 의도와 클릭 확인, 선택한 질문 묶음을 관리합니다. 안내는 포커스를 옮기거나 입력하지 않습니다. 입력/IME/단순 통과/ON-OFF 전환은 대기 타이머를 취소합니다. 실제 입력 성공 뒤에만 그 묶음의 체크를 해제합니다.
- 글씨 크기 정규화는 System/Custom 두 모드이며 기본 System입니다. 구 Current 값은 System으로 읽고 Custom 퍼센트는 유지합니다. 숫자와 슬라이더는 같은 크기 상태를 사용합니다.
- `DEFAULT_COLOR`는 새 질문의 purple이며 purple 팔레트는 아이콘의 #6554e8입니다. 저장된 질문을 쓰거나 색 키를 마이그레이션하지 않습니다. `colorOf`의 구버전 색 없음→yellow 계약은 유지합니다.


## 0.8.1: 숨김 상태와 도구 모음 복원

- `ui/panel.js`의 `hiddenByUser`는 현재 콘텐츠 스크립트 인스턴스에만 속합니다. 질문·체크·설정 저장소를 쓰지 않습니다. `hide()`는 메뉴를 숨기고 자동 패널 열기를 억제합니다.
- `fromToolbar()`는 숨겼던 경우 작은 메뉴를 복원하며, 보이는 경우 기존 패널 열기 동작을 유지합니다. 앱의 기존 단일 인스턴스 진입점은 이 메서드에 연결합니다.
- `background.js`의 도구 모음 클릭→content.js 재주입 흐름과 배포 권한은 변경하지 않습니다. 재주입은 기존 인스턴스를 재사용하므로 질문 UI와 이벤트가 중복되지 않습니다.
- 숨기기 버튼은 임시 선택/입력 안내·미리보기만 닫고 작성 세션이나 읽기 모드를 변경하지 않습니다. 새로고침에서는 기존처럼 기본 작은 메뉴로 시작합니다.


## 0.9.0: 언어 모듈

- `src/i18n/messages.js`는 제품이 제공하는 한국어 문구와 영문 번역 목록, `i18n/index.js`는 언어 검증·보간을 담당하는 순수 함수입니다. 기본/미지원 언어는 `ko`이며 명시적으로 선택한 `en`만 영어로 사용합니다.
- `ui/language.js`는 `qb:appearance:language:v1` 한 키만 저장하고 초기 읽기/변경 경쟁과 다른 탭 동기화를 관리합니다. 질문·체크·원문 어댑터에 의존하지 않습니다. DOM이 만들어질 때 정적 UI 텍스트 노드·속성만 한 번 연결하며, 사용자 질문이나 인용을 나중에 훑어 번역하지 않습니다.
- 언어 전환은 기존 노드의 UI 문구만 바꿉니다. textarea 값/커서/포커스, 작성 세션, 메뉴 숨김 상태와 사용자 편집 미리보기를 보존합니다. 동적 번호·상태·색상 이름은 컨트롤러가 번역 함수를 주입받아 표시합니다.
- `domain/prompt.js`는 생성 시 언어를 받아 항목명만 번역합니다. 원문·질문은 원래 문자열을 사용하고, 두 언어의 원문/질문 쌍을 모두 검사해 언어 전환 뒤 중복 추가를 막습니다.
- `src/background.js`도 같은 번역 목록으로 도구 모음 제목을 표시합니다. 빌더가 content.js와 background.js를 각각 묶으며 배포 권한이나 외부 리소스를 추가하지 않습니다. 생성된 두 파일 모두 직접 편집하지 않습니다.
- `language-test.cjs`는 지연된 읽기, 원문과 질문 보존, 실제 MV3의 양 언어 취소 반복·작성 중 변경·저장·다른 탭·새로고침·입력·표시 크기를 검사합니다. 모듈 계약은 언어 설정에서도 핵심 데이터 접근을 금지합니다.


## 0.9.1: 백업 투영과 파일 이름

- `domain/backup.js`는 저장 데이터와 현재 페이지의 제목·주소·범위를 명시적으로 받아 새 백업 객체/파일명만 반환합니다. DOM·네트워크·저장소 쓰기에 접근하지 않습니다. 모듈 계약 검사로 이 경계를 확인합니다.
- 서비스명·대화 제목·안전한 파일명·로컬/UTC 시각·대화별 색인을 담당합니다. ChatGPT의 프로젝트 경로가 달라도 같은 대화 ID는 한 묶음이며, 다른 서비스는 기존 URL 단위를 유지합니다. 기존 질문과 원문 위치·체크 키를 바꾸지 않습니다.
- 앱은 다운로드 버튼 클릭 순간 페이지 정보를 캡처한 뒤 저장소를 읽습니다. 읽기 중 SPA가 다른 대화로 이동해도 새 제목을 앞 대화에 붙이지 않습니다. 이전 주소 기록 보기에서는 현재 대화 제목을 차용하지 않습니다.
- 전체 백업은 기존 `data`와 설정을 유지하고 `version:4`에 제목·날짜·대화별 목록을 추가합니다. 현재 대화 백업은 해당 질문·체크만 담습니다. 가져오기는 기존 포맷·질문/키 검증과 병합 규칙으로 v3/v4를 모두 읽습니다.
- 현재 페이지 외의 제목은 저장 당시 기록에서만 확인합니다. 오래된 백업에 제목이 없으면 unavailable로 표시합니다. JSON의 실제 질문·원문과 제목은 파일명 정제나 UI 언어 전환으로 재작성하지 않습니다.
