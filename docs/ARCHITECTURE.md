# AskMarker 모듈 구조

## 검토 결과와 적용 원칙

0.6.4는 CSS, 화면 생성, 선택 인식, 원문 위치 복원, 작성 상태, 저장, 프롬프트 입력이 하나의 즉시 실행 함수에 들어 있었습니다. 글꼴처럼 표시만 바꾸는 기능도 같은 파일을 수정해야 했고, 일반 입력창 제외 규칙이 ChatGPT의 메일 작성 박스까지 막았습니다.

0.7.0은 **변경 이유가 같은 코드를 한 모듈에 모으는 단일 책임 원칙**, **모듈 내부 상태 은닉**, **콜백을 통한 의존성 주입**, **순수 데이터 처리와 DOM·저장소 부작용의 분리**를 적용합니다. 파일을 나눠 같은 전역 변수를 공유하는 방식은 사용하지 않습니다. 각 파일은 CommonJS 모듈 스코프를 가지며, 명시적으로 가져온 API만 사용합니다.

모듈화가 모든 영향 가능성을 없애지는 않습니다. 예를 들어 글꼴을 바꾸면 줄바꿈과 원문의 화면 좌표는 달라집니다. 따라서 좌표를 원문의 식별자로 저장하지 않고 정확한 메시지 ID·텍스트·오프셋으로 연결하며, 말풍선은 문서 흐름 안에 둡니다. 변경 범위를 구조적으로 줄이고 경계 검증으로 남은 영향을 확인합니다.

## 책임과 변경 위치

| 위치 | 책임 | 접근하지 않는 상태 |
| --- | --- | --- |
| `src/domain/notes.js` | 기존 저장 키와 질문 유효성 계약 | 화면, 브라우저 이벤트 |
| `src/domain/prompt.js` | 원문·질문·번호를 그대로 프롬프트로 변환 | DOM, 저장소 |
| `src/domain/colors.js` | 색상 이름·형광펜·포인터 색상 값 | 질문 저장, 원문 선택 |
| `src/domain/appearance.js` | 로컬 글꼴 목록·진하기 범위·설정 키 | 질문, 체크 상태 |
| `src/storage/queue.js` | 키별 쓰기 순서와 진행 상태 | UI, 원문 인식 |
| `src/storage/prompt-choices.js` | 체크 상태, 늦게 온 읽기/쓰기 충돌, 다른 탭 동기화 | 질문 내용, 형광펜, DOM |
| `src/platform/selectors.js` | ChatGPT의 답변·입력창·작성 박스 경계 | 저장, 화면 설정 |
| `src/platform/source.js` | 선택 허용, 원문 인덱스, 정확한 위치 복원, 배치 기준 | 저장소, 글꼴/포인터 설정 |
| `src/platform/composer.js` | 기존 입력 보존, 중복 방지, 입력 후 수락 확인 | 질문 목록, 체크 상태 |
| `src/ui/appearance.js` | 글꼴·포인터 진하기와 전용 설정 저장 | 질문/선택/원문/입력 어댑터 |
| `src/ui/panel.js` | 펼침·접힘과 읽기 버튼 표시 | 질문 저장, 초안, 프롬프트 |
| `src/ui/cards.js` | 질문 카드 DOM과 사용자 동작 콜백 | 직접 저장소 쓰기 |
| `src/ui/base.css`, `panel.css`, `shell.html`, `shell.js` | 공통 디자인 값·레이아웃·정적인 화면 생성 | 핵심 데이터 처리 |
| `src/app.js` | 조립, 작성/저장/취소 생명주기, 상태를 화면에 전달, 탐색·이벤트 연결 | 다른 모듈의 비공개 변수 |

`app.js`는 아직 전체 사용 흐름을 조정합니다. 새 기능을 추가할 때 코드를 무조건 이 파일에 넣지 않습니다. 별도 변경 이유가 있으면 모듈을 만들고 조립에 필요한 호출만 여기에 둡니다. 현재는 단일 컨트롤러로 상태 전환을 추적하기 쉬운 규모이므로 프레임워크·전역 이벤트 버스·추상 플러그인 시스템을 도입하지 않았습니다.

## 반드시 유지할 계약

- 표시 설정은 `qb:appearance:*`에만 저장합니다. `qb:note:`와 `qb:prompt-choice:`를 수정하지 않습니다.
- 글꼴·포인터 설정은 전체 질문 화면 재생성을 호출하지 않습니다. CSS만 바꾸므로 작성 내용·포커스·원문 연결을 재설정하지 않습니다.
- 글꼴은 외부 다운로드 없이 로컬/시스템 글꼴을 사용합니다. AskMarker UI와 읽기 모드의 답변 문단에 적용하고 코드 글꼴은 유지합니다. 없는 글꼴은 지정된 기본 계열로 대체됩니다.
- 원문 저장은 화면 좌표가 아닌 원문 식별 정보에 의존합니다. 기존 `include-buttons`/이전 인덱스 규칙은 그대로 유지하고, 새 기록만 `answer-content` 인덱스를 사용합니다.
- ChatGPT 작성 박스는 확인된 답변 안에서만 허용합니다. 실제 입력창·사용자 메시지·관련 없는 편집기까지 허용하지 않습니다.
- 말풍선을 ProseMirror/코드 스크롤 영역 안에 삽입하지 않습니다. 박스가 끝난 아래에 둬 편집기 문서를 오염시키거나 잘리지 않게 합니다.
- 입력 어댑터가 실제 추가 결과를 확인한 뒤 컨트롤러가 전달한 묶음의 체크를 해제합니다. 추가 도중 저장한 새 질문은 해제하지 않습니다. 실패·취소·단순 복사는 해제하지 않습니다.
- 질문 내용, 활성 색상 대상, 프롬프트 포함 여부, 읽기 모드, 패널 표시 상태는 서로 다른 상태입니다.

## 앞으로 글자 크기를 추가한다면

1. `domain/appearance.js`에 크기 범위와 별도 설정 키를 정의합니다.
2. `ui/appearance.js`에서 CSS 변수 하나와 설정 컨트롤을 연결합니다.
3. 필요한 `ui/*.css`에서 그 변수를 사용합니다. 원문 텍스트·저장 형식·프롬프트 코드는 바꾸지 않습니다.
4. `appearance-delivery-test.cjs`에 작성 중 크기 변경, 스크롤·줄바꿈, 저장 데이터 동일성 검증을 추가합니다.

## 빌드와 검사

```sh
npm run build
npm run check:build
npm test
python scripts/package.py
```

`content.js`는 배포용 생성물입니다. 직접 수정하지 않습니다. 의존성 없는 정적 빌더가 `src/`의 상대 경로 모듈과 CSS/HTML을 하나의 MV3 콘텐츠 스크립트로 묶습니다. `eval`, 외부 로더, 네트워크 요청은 없습니다. 기존 설치 폴더의 전체 런타임 파일과 하위 폴더를 덮어써 확장 ID·기록을 유지합니다. 현재 런타임에는 `assets/`의 고정 MarkChat PNG가 포함됩니다.

`module-contract-test.cjs`는 브라우저 없이 순수 함수·저장 상태와 의존 경계를 검사합니다. `appearance-delivery-test.cjs`는 실제 확장 환경에서 설정 변경 중 초안·저장 기록·체크 상태·코드 글꼴 보존을 검사합니다. 전체 회귀 모음은 취소 재선택, DOM 교체, 이전 저장 기록, 여러 대화, 입력창 처리까지 확인합니다.

## 0.7.4: 단일 기본 아이콘

- `manifest.json`의 `icons`·`action.default_icon`은 MarkChat PNG만 참조합니다. 옵션 페이지와 아이콘 선택 모듈·패널 버튼·메시지 처리를 제거했습니다.
- `background.js`는 설치/업데이트 이벤트와 워커 시작 시 기본 아이콘을 적용하고 폐기한 `qb:appearance:icon:v1` 한 키만 정리합니다. 질문·체크·읽기 설정에는 접근하지 않습니다.
- 기존 도구 모음 클릭의 콘텐츠 스크립트 실행은 유지합니다. 팝업이나 옵션 메뉴를 추가하지 않습니다.
- `assets/icons/`에는 MarkChat의 원본 SVG와 16·24·32·48·128·256px PNG만 있습니다. `scripts/render-icons.cjs`는 개발용 재생성 도구입니다.
